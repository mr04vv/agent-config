# Global Instructions

## 進め方

- 実装に入る前に、作業のスコープと影響範囲を明確にすること
- コードや文脈から判断できない決定は依頼者に質問すること。推測や仮定で進める場合はその旨を明示すること
- ライブラリや API の仕様に関わる判断では、公式ドキュメントやリリースノートを確認すること

## 言語

- 出力や回答は日本語で行うこと
- コード中のコメントはプロジェクトの既存の慣習に合わせること（既存コメントがない場合は英語）

## コーディング

- 意味を持つ数値や、複数箇所で使う値は定数として定義すること
- エラーを握り潰さないこと
- 不要なコードやコメントアウトされたコードを残さないこと

## Git

- 1つのコミットには1つの論理的な変更のみを含め、コミット前に差分を確認すること
- `.gitignore` に含まれるべきファイル（環境変数、ビルド成果物、依存パッケージ等）をコミットしないこと

## テスト

- テスト可能なロジックを変更する場合は、t-wada（和田卓人）氏が提唱する TDD（Red → Green → Refactor）のサイクルに従うこと。新機能はテストを先に書き、バグ修正はそのバグを再現するテストを先に書く

## スコープ

- 依頼された作業範囲を超えたリファクタリングや改善は行わないこと。気づいた改善点・技術的負債・潜在的なバグ・明らかなパフォーマンス問題は、修正せず報告にとどめること
- README や関連ドキュメントに影響する変更は、更新の要否と内容を依頼者に確認してから対応すること

## 出力

- 作業結果やレポートの出力を依頼された場合は Markdown ファイル（`.md`）として作成し、ファイル名と保存先は依頼者に確認するかプロジェクトの慣習に合わせること

## 作業終了時

変更内容のサマリー、残存する課題やリスク、推奨する次のステップを日本語で報告すること。
